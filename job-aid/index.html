Running a records migration and resolving records held for review

Use this guide each time new records are migrated. It tells you what to do, in what order, what “done” looks like, and who to contact when something goes wrong.
Who uses itProject assistant, records team
WhenEvery migration run
You produceExcel workbook, status report
You needLatest export, Excel

1The process at a glance

2Step by step

  1. Save the latest export. Put the newest legacy files (legacy_people.csv, legacy_awards.csv) in the project’s data folder on the secured project drive.
    both files are in the folder and dated today.
  2. Run the migration. Run python -m rmig. It cleans, checks and loads the records, then prints 6 reconciliation checks.
    every check in the printout shows [x]. If any does not, go to section 4 and escalate.
  3. Open the workbook. Open output/migration_workbook.xlsx and look at three sheets: Summary (totals), Reconciliation (every check says Pass, each faculty’s difference is 0) and Needs Review (records held back).
    Reconciliation shows Pass for all 6 checks and 0 difference for every faculty.
  4. Send the held records. Send the Needs Review list to the records team. Share record IDs and the open_issues reason only, never the full export (see section 5). Section 3 tells them how to fix each reason.
    the records team has confirmed they received the list.
  5. Update the tracker. In the workbook, update the Schedule, Risk Register, Project Issues and Action Items sheets, then send output/status_report.md to the project lead.
    the status report is sent and the tracker shows today’s date.
  6. Repeat after fixes. When the records team says which award IDs they fixed, get a new export and repeat from step 1. Fixed records move from Needs Review into the new system.
    Needs Review is empty (or every remaining record has an owner and a date), then move to testing and sign-off.

3Why a record was held, and how to fix it

CodeWhat it meansHow the records team fixes it in the source system
DQ-05Amount missing or not a number (e.g. “TBD”)Enter the awarded amount in dollars
DQ-06Amount is negativeCheck the award letter and correct the amount
DQ-07End date is before start dateCheck the award letter; usually the dates were swapped
DQ-08Title is missingEnter the project title from the application
DQ-09No principal investigator (PI)Add the PI’s person ID
DQ-10PI ID is not in the people listAdd the researcher to the people list, or correct the ID
DQ-12Possible duplicate of another awardCompare both records; if they are the same award, retire one
No action needed: faculty names, status codes, date formats, amounts with commas, exact duplicate rows and researchers entered twice are fixed automatically and listed in the Issue Log sheet for audit. Invalid emails (DQ-13) are migrated but flagged: send the correct address to the project assistant.

4When to escalate

If this happensTellWhen
Any reconciliation check fails (counts or dollar totals don’t match)Project leadSame day. Stop: do not send results.
Held records are not fixed within two weeksProject leadSame day the two weeks pass
Personal information is found outside the secured project driveProject leadSame day, immediately
You are not sure what an issue code meansProject assistantBefore you change anything

5Keep personal information safe

Research records contain personal information. Work only on the secured project drive. Share summaries and record IDs, not raw exports. Never email an export.

6Before you finish: checklist

  • All 6 reconciliation checks pass
  • Every faculty shows a difference of 0
  • Needs Review list sent (IDs and reasons only)
  • Tracker sheets updated with today’s date
  • Status report sent to the project lead
  • Anything that needed escalating was escalated today
  • No exports saved outside the secured drive
  • Next run date agreed with the records team
